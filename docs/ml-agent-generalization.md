# 문맥 탐지와 근거 조사 에이전트 설계

2026-10-21. 기준 코드: `ff6ba7746930fd71d298775d8b1521cf490652a9` / 0.6.2.

이 문서는 최초 검토 시점의 구현 제안이다. 이후 **탐색 그래프·영역 근거 저장·변경 비교·Unicode 문자 확장·Groq 수집 근거 조사**를 개발 소스에 구현했다. 현재 동작·명령·검증 범위는 [구현 안내](inspection-agent.md)를 기준으로 한다. 아래의 ML 학습 모델·영역 자동 분할·브라우저 재관측 도구는 여전히 후속 제안이다. 최초 오프라인 비교 수치는 당시 엔진 해시의 기록으로 보존한다.

## 판단

추가할 수 있다. 다만 Random Forest 자체보다 **새 사이트에서도 같은 단위로 문맥을 수집하고, 관측 사실과 추정·미확인을 구분하는 설계**가 우선이다. 일반적인 키워드 점수에 LLM 설명만 붙이면 수집 단계에서 놓친 게시글은 계속 놓친다.

권장 흐름은 `DOM 수집 → 게시글·댓글별 영역 구성 → 규칙과 ML의 병렬 후보 검색 → 부족한 근거 조사 → 구조화된 검토 제안 → 사람 검토`다. 필수 4종은 실제 문자·스타일 근거로 판정하고, ML은 광고 문맥과 검토 순서를 보조한다. 피싱과 법적 불법성은 별도 목표로 남긴다.

## 실험 결과를 읽는 방법

[전달 리뷰 원문](../research/ml-review/2026-10-21/originals/review-and-results.md)은 직접 관찰 73건(광고 의심 50, 정상 23)을 대상으로 5-fold 그룹 분할을 사용했다. 간접 보고 5건은 제외했다. 아래 참고 모델 수치는 전달된 사례별 예측에서 다시 계산해 원래 혼동행렬과 일치하는지 확인했다. **RF를 재학습하거나 원래 실험 환경을 재현한 것은 아니다.**

| 비교 | 광고 의심 추출 / 50 | 정상 문구 추출 / 23 | 광고 의심 미추출 / 50 |
| --- | ---: | ---: | ---: |
| 전달 프로토타입: 정규화 키워드 | 40 | 12 | 10 |
| 전달 프로토타입: 문자 TF-IDF + RF | 33 | 6 | 17 |
| 현재 Chickadee `analyze_candidate`, 원문 조각만 입력 | 18 | 0 | 32 |
| 현재 규칙 또는 전달 RF가 추출한 집합, 진단용 가상 합집합 | 39 | 6 | 11 |

현재 엔진 대조에는 원문 `evidence_text`만 넣었다. 원본 페이지·광고 링크를 방문하지 않았고, CSS·제목·부모 문맥을 만들어 넣지 않았다. 미추출은 정상 확정이 아니다. 현재 규칙은 이 조사 자료에서 파생한 회귀 사례를 이미 반영했으므로 독립 평가셋이 아니며, RF는 수집자 삭제 마커를 제거한 입력을 사용해 전처리도 다르다. 가상 합집합은 배포된 하이브리드의 성능이 아니다.

이 비교가 보여 주는 것은 두 방법의 누락이 다르다는 점이다. RF만 추출한 광고 의심 조각은 21개, 현재 규칙만 추출한 조각은 6개다. RF를 최종 통과 조건으로 두면 규칙이 찾은 일부를 다시 잃는다. 반대로 기존 후보에만 ML을 적용하면 RF가 별도로 찾을 수 있는 영역이 애초에 입력되지 않는다.

예를 들어 `A001`의 ‘안전하고 신뢰할 수 있는 토토 및 카지노 사이트를 찾고 계신가요?’는 현재의 좁은 권유 신호로 잡지 못했다. `A004`의 첫충·매충 비율 문구는 주제어 없이 혜택만 제시한다. `A010/A011`의 `CΟΜ`이나 `A044`의 일반적인 이벤트 문구는 조각만으로 판정할 수 없다. 앞의 사례에는 문맥 검색을 넓힐 여지가 있지만, 뒤의 사례에는 같은 게시글의 추가 근거가 필요하다. 사례를 외워 전부 양성으로 만드는 것은 개선이 아니다.

전달 자료의 ‘정책 테스트 12개 통과’는 결정론적 합성 함수의 계약 시험이다. 실제 LLM의 판단·도구 선택·프롬프트 주입 저항성은 시험하지 않았다. 참고 detector의 이력에 있는 TP 75 / FP 1 / FN 0도 해당 저장소의 모의 페이지 결과이며, 우리 프로그램이나 실제 사이트의 성능으로 인용하지 않는다. 그 구현의 `--strict`는 알려진 오탐을 허용한다.

## 일반화할 입력과 판정 단위

### 사이트마다 바뀌는 선택자보다 콘텐츠 영역

현재 수집기는 `[data-comment-id]`, `[role=article]`, `article`, `[data-post-id]`를 `content_scope`로 사용한다. 이런 마크업이 없는 게시판에는 사이트별 설정이 필요하다. 다음 수집 계층은 제목·본문·댓글·반복 목록·탐색 메뉴의 구조를 보고 영역을 구성하되, 경계가 애매하면 `scope_quality=uncertain`으로 남긴다. 이 단계의 규칙과 ML은 전체 DOM 영역을 입력받아야 하며 `ad_candidates`만 재분류해서는 안 된다.

한 게시글 안의 제목·본문은 관계를 연결할 수 있지만, 서로 다른 댓글이나 페이지 제목과 댓글을 하나의 문자열로 합쳐 광고 근거를 만들지 않는다. 태그 사이 단어는 원문 offset과 `text_breaks`를 유지해 복원한다. 부모·자식이 같은 내용을 담으면 최소 근거 영역을 대표로 잡고, 상위 문맥은 참조로 보관한다. iframe은 frame 경로까지 식별자에 포함한다.

### 같은 증거 패킷, 독립된 판단 축

| 축 | 기록할 관측 사실·출력 | 주의점 |
| --- | --- | --- |
| 콘텐츠 | 원문·근접 문맥·권유/연락 수단·인용/예방 표현, `ad_suspected / benign_context / uncertain` | 광고 주제어만으로 법적 판정하지 않음 |
| 문자 변형 | 복원 문자열·변환 종류·원문 span·관련 키워드 | 영어·상품명·한글 자판 변환을 무조건 광고로 처리하지 않음 |
| 표시 상태 | computed style, 조상 효과, box, 스크롤·viewport, 배경 불확실성 | 선언된 CSS와 실제 렌더링 구분. 미수집은 null |
| 위치·범위 | run/page/frame/snapshot/scope/selector, 수집 시각·동작 순번 | DOM 변경 뒤 같은 selector가 같은 글이라는 보장 없음 |
| 수집 범위 | 실패한 페이지·iframe·요소 한도·읽기 동작 한도·차단 이유 | 미검사를 정상 0건으로 집계하지 않음 |
| 목적지·피싱 | 링크 문자열의 구조적 특징, 목적지 확인 상태 | 외부 링크는 기본적으로 방문하지 않음. 별도 검증 없으면 피싱 unknown |

특정 키워드 목록을 계속 늘리는 대신, ‘표시된 콘텐츠와 숨김 콘텐츠’, ‘광고 주제와 가입·결제·연락 유도’, ‘자기 홍보와 타인의 광고를 인용한 기사’의 관계를 학습·검증한다. 이 관계는 게시판 제품이 달라져도 유지될 가능성이 높다. 화면 숨김 자체는 접근성·메뉴에서도 쓰이므로 광고 문맥과 분리해 판단한다.

추후 확장할 패턴은 키워드 도배, 이미지 중심 광고, 조건별 화면 차이 등이다. 이들은 보조 패턴으로 먼저 기록한다. 모바일/PC나 접속 경로별 차이도 비교 실험의 관측일 뿐 곧바로 악성 클로킹 판정이 되지는 않는다. 현재 필수 4종 코드에 임의로 끼워 넣지 않는다.

## ML을 붙일 위치

먼저 `문자 n-gram + 로지스틱 회귀`, 작은 RF, 현재 규칙을 같은 분할에서 비교한다. 문자 n-gram은 띄어쓰기·변형 표기에 대응할 수 있는 기준 모델이고, RF는 밀도·거리·변형 비율·DOM 역할 같은 구조화된 특징의 기준 모델로 비교한다. 어느 쪽이 우월한지는 아직 확인하지 않았다. 작은 전달 표본으로 임베딩 모델이나 파인튜닝의 우월성을 주장할 수 없다.

학습 입력은 주제·권유의 근접성, 예방/인용 문맥, 문자 복원 전후 차이, 문장 길이, 링크와 주제 사이 거리, 영역 역할 및 관측된 스타일 특징이다. URL 식별자·기관명·수집자의 판정 이유·정답 기법은 제외한다. 누락 특징은 별도 missing mask로 표현한다. 도메인 평판으로 게시글 검사를 생략하지 않는다.

후보 검색은 기존 규칙의 확실한 결과를 유지하면서, 규칙 미추출 영역 중 ML이 의심하거나 문맥이 불완전한 것을 별도 조사 큐에 넣는다. 규칙과 모델의 충돌, 짧은 조각, 이미지 배경 때문에 확인되지 않은 대비 등을 에이전트 호출 조건으로 삼는다. 모든 후보를 LLM에 보내지 않는다. ML 점수는 검토 우선순위이며 보정·외부 평가 전에는 ‘불법 확률 92%’처럼 표시하지 않는다.

## Groq 근거 조사 에이전트

gayadi의 `PlaceRecommendationAgent`와 `GroqRecommendationLanguageModel`은 모델이 계획을 만들고, 애플리케이션이 허용된 검색을 실행하며, 허용 후보 안에서 결과를 검증하는 구조다. Chickadee에서도 같은 책임 분리를 사용할 수 있다. Java·Spring 의존성을 가져오지 않고 Python 어댑터와 기존 로컬 bridge를 연결한다. 기존 프로젝트의 API 키나 설정 파일을 복사하지 않는다.

### 현재 도구와 필요한 도구

현재 `chickadee/tools.py`는 도구 9개와 JSON Schema를 제공하지만 `agent_connected=false`다. `scan.findings`는 탐지된 결과를 읽을 뿐, 미추출 영역이나 현재 DOM의 부모 스타일을 조회하는 기능은 없다.

| 도구 | 상태 | 근거 조사에서의 용도 |
| --- | --- | --- |
| `scan.status`, `scan.findings`, `scan.events` | 구현됨 | 실행 식별과 수집된 결과·진행 상황 조회 |
| `scan.start`, `scan.pause/resume/stop`, `workflow.validate` | 구현됨 | 사용자 실행 제어 계층. 개별 근거 조사 모델에는 기본 제공하지 않음 |
| `review.update` | 구현됨 | 검토 기록 쓰기. 근거 조사 모델의 기본 도구에서 제외 |
| `evidence.list_scopes` | 제안 | 동일 snapshot에서 미추출 영역까지 제한된 페이지 크기로 조회 |
| `evidence.read_scope` | 제안 | 지정한 scope의 원문·부모 문맥·링크 문자열·관측 스타일 조회 |
| `evidence.recheck` | 제안 | 허용된 현재 페이지의 selector 유일성·텍스트 hash·computed style·box 재관측 |
| `inspection.read_control` | 제안 | 수집기가 사전 등록한 읽기 동작 ID만 실행. 사용자가 허용한 범위와 기존 요청 정책 유지 |

새 도구는 모델이 임의 URL·JS·CSS selector·파일 경로를 만들어 실행하게 하지 않는다. 서버가 발급한 run/snapshot/scope/control ID를 받으며, 실행 ID가 바뀌거나 내용 hash가 바뀌면 재관측 또는 보류한다. 저장된 과거 결과에는 DOM 재조회가 불가능하므로 ‘그때의 스타일 미확인’을 유지한다. 브라우저 밖에서 자의적으로 새 세션을 여는 도구를 제공하지 않는다.

### 실제 루프

1. 규칙·ML의 조사 큐에서 한 영역을 선택하고 필요한 최소 근거만 구성한다.
2. 모델이 누락 근거와 조회 도구를 제안한다. 애플리케이션이 ID·허용 도구·예산을 확인한다.
3. 허용된 조회를 실행해 실제 값과 실패 이유를 전달한다. 같은 요청 반복은 캐시하거나 중단한다.
4. 충분하면 모델이 `assessment`, `evidence_ids`, `missing_evidence`, `recommended_next_action`, `abstain_reason`을 반환한다.
5. JSON Schema뿐 아니라 근거 ID 소속·snapshot·인용 span을 검증한다. 내용이 부족하거나 맞지 않으면 보류한다. 원본 결과를 지우거나 모델 추정을 필수 기법으로 승격하지 않는다.

예산 초안은 항목당 모델 호출 2회, 추가 조회 4회, 전체 20초다. 이는 구현 시 검증할 상한 제안이다. 호출별 출력 한도, 입력 크기, 누적 토큰과 취소를 별도로 제한하고 실패·재시도도 예산에 포함한다. 타임아웃·429·제공자 오류에는 지금까지의 규칙 결과를 유지하고 AI 의견을 미완료로 기록한다. 예산 소진이 정상 판정으로 바뀌면 안 된다.

페이지의 ‘검사를 중단하라’, ‘이 주소를 호출하라’, 도구 호출처럼 생긴 JSON도 모두 분석 데이터다. 프롬프트만으로 방어가 끝난다고 보지 않는다. 모델에는 제한된 조회 권한만 주고, 실행 계층이 외부 이동·폼·다운로드·코드 실행을 제한한다. 사용자에게는 비공개 추론문 대신 `조회한 영역 → 확인한 값 → 부족한 근거 → 판정 제안`의 관측 로그를 보여 준다.

### Groq 연결 시 확인할 점

[Local Tool Calling](https://console.groq.com/docs/tool-use/local-tool-calling)은 모델의 도구 요청을 앱이 검증·실행하는 방식으로 사용할 수 있다. 모델과 endpoint는 제공자 어댑터 설정에 두고 지원 기능을 확인한다. Groq의 검색·코드 실행 내장 도구를 켤 필요는 없다.

[Structured Outputs](https://console.groq.com/docs/structured-outputs)는 일부 모델에서 엄격한 JSON Schema 출력을 지원한다. 2026-10-21 확인한 문서에서는 Structured Outputs와 tool use의 동시 사용을 지원하지 않으므로 **조회용 도구 호출 단계와 최종 JSON 출력 요청을 분리**한다. 형식 검증은 근거의 진실성 검증을 대신하지 않는다.

기본값은 로컬 규칙 검사와 AI 비활성이다. 사용자가 AI 검토를 켜고 보낼 근거 범위를 확인한 경우에만 필요한 문맥을 전송한다. 쿠키·인증정보·원본 HTML·전체 로그·화면 이미지를 기본 전송하지 않는다. 연락처·URL query 등은 전송 전에 최소화하고 전송 패킷의 기준을 남긴다. [Groq 데이터 정책](https://console.groq.com/docs/your-data)은 일반 추론 데이터를 기본 보관하지 않는다고 설명하지만, 장애·남용 조사 등 예외와 별도 데이터 제어가 있으므로 ‘어떤 경우에도 저장되지 않는다’고 안내하지 않는다.

이번 검토에서는 Groq API를 호출하거나 조사 자료를 외부 모델에 전송하지 않았다.

## 저장과 화면 연결

필수 `result.json`과 기존 17칼럼 CSV는 유지한다. 제안된 확장 자료는 `evidence-packets.jsonl`(관측), `agent-events.jsonl`(도구 실행·실패·소요 시간), `agent-assessments.json`(제안·보류·사용량)에 나눠 저장하고 원본 결과 SHA-256과 연결한다. 이 파일들은 **현재 생성되는 파일이 아니다.**

패킷은 run/page/frame/snapshot/scope/evidence ID, 원문 span, 텍스트 hash, computed style·box 또는 null, 누락 이유, 수집 시각·동작 순번을 담는다. 모델 제안에는 모델·프롬프트 버전·입력 패킷 hash·사용량을 기록한다. 사람의 `review.json`과 별개로 두고 충돌 시 사람 검토를 덮어쓰지 않는다. 데이터는 크기·보관 개수 제한을 둔다.

화면은 기존 흐름 그래프의 수집·탐지 뒤에 선택적인 ‘문맥 분석’과 ‘근거 조사’를 연결한다. 조사 중인 페이지·영역, 실제 도구 동작, 성공·미확인·보류와 최종 근거를 표시한다. 별도 준비 문구·연결 배지·장식 띠를 늘리지 않는다. 기존 미리보기와 실행 기록에서 같은 snapshot을 열고, 모델 추정과 실제 관측은 상세 패널에서 구분한다.

## 성능을 확인할 기준과 구현 순서

| 순서 | 실제 변경 | 완료를 판단할 증거 |
| --- | --- | --- |
| 1 | 미추출 영역을 포함한 증거 패킷·범위 품질·미검사 기록 | 서로 다른 댓글 혼합 없음, selector/frame/span 검사, 현재 필수 결과 회귀 유지 |
| 2 | n-gram 선형 모델·구조 특징 RF 비교, 별도 조사 큐 | 데이터 그룹·학습 누수 감사, 기관·시기 외부 holdout에서 오탐/누락/보류 비교 |
| 3 | 제한된 조회 도구와 고정 추가조회 정책 | 로컬 fixture에서 메뉴·기사·숨김 조상·중첩 frame·DOM 변경·권한 거부 검증 |
| 4 | opt-in Groq 어댑터와 구조화된 검토 제안 | 실제 도구 호출·취소·오류·예산·잘못된 근거 ID·페이지 지시문 시험, 동등 예산에서 순이득 확인 |
| 5 | 흐름 그래프·미리보기·기록과 연결, Windows 배포 | 실제 패키지 동작 검증. 소스 테스트와 패키지 검증을 별도로 보고 |

평가는 A 현재 규칙 / B 규칙+ML / C B+고정 추가조회 / D B+에이전트를 같은 데이터·같은 추가조회 예산에서 비교한다. **D-C가 추론에 의한 이득**이고, D-B만으로는 단순히 더 많이 읽은 효과와 구분할 수 없다. 후보 큐가 실제로 얼마나 많은 영역을 놓치는지도 함께 측정한다.

학습·검증은 같은 도메인·게시판·캠페인·유사 문구가 양쪽에 섞이지 않도록 연결 그룹으로 분리한다. 전달 리뷰의 도메인 근사는 PSL이 아니므로 정식 suffix/호스팅 tenant 처리가 필요하다. TF-IDF·특징 선택·임계값은 학습 fold 안에서만 맞춘다. 기존 자료는 개발용으로 고정하고 새로운 기관·시기의 외부 평가셋을 확보한다. 모델 의견을 그대로 다음 학습의 정답으로 넣지 않는다.

지표는 콘텐츠 TP/FP/FN·PR-AUC·보류율·검토 작업량, 필수 기법별 precision/recall, 위치·span·frame 정확도, 중복·미검사 비율, 요청·시간·토큰 비용을 분리한다. 정상 경고 기사 속 URL·전화번호, 접근성 숨김, 메뉴, 일반 스크롤, 이미지 배경, 다국어 광고와 사이트별 DOM 변경을 포함해야 한다. 실제 LLM 시험과 결정론적 정책 시험도 구분한다.

현재 시점에서 가장 먼저 구현할 것은 **증거 패킷과 미추출 영역의 조사 큐**다. 이 입력 계층을 갖추면 규칙·작은 ML·Groq를 교체하며 같은 기준으로 비교할 수 있고, 특정 모델이나 한 게시판 구조에 종속되는 일을 줄일 수 있다.
