# 공모전 요구사항 정리

출처: 「공공 웹사이트 불법광고 탐지 도구 개발 공모전 모집요강」, 2026년 9월. 페이지는 PDF에 표시된 쪽 번호입니다. 아래의 **필수**는 공모전 제출 조건이며, 개발 방식은 [개발 계획](development-plan.md)의 제안입니다.

## 입력·탐지·화면

| 구분 | 요구사항 | 근거 |
| --- | --- | --- |
| 입력 | 진입 웹사이트 URL 1개 | 8~9쪽, 붙임3 |
| 탐색 | 하위 페이지, 게시글, 댓글, 삽입 iframe 내부 등 다양한 영역 | 5쪽, 붙임1 |
| 탐지 | `HOMOGLYPH`, `JAMO`, `TRANSPARENT`, `OFFSCREEN` 4종 필수 | 5쪽, 붙임1 |
| 화면 | 탐지 결과를 사용자가 확인하는 화면 필수 | 5쪽, 붙임1 |
| 환경 | Windows 11, GPU 없는 일반 PC에서 실행 | 8쪽, 붙임3 |
| AI | 적용 여부 선택. 로컬 추론은 CPU·RAM 기반 | 1·8쪽 |
| 결과 | 화면과 별도로 `result.json` 필수 생성 | 9~14쪽, 붙임3~4 |
| 확장 | 추가 유형을 구현하면 `result_extra.json` 별도 생성 | 5·9·11쪽 |

## result.json 규칙

| 항목 | 조건 |
| --- | --- |
| 파일 | 이름 `result.json`, UTF-8, BOM 없음, JSON |
| 위치 | 구동 파일 폴더가 원칙. 다른 위치는 사용설명서 첫 장에 파일별 경로 명시 |
| 최상위 | `meta`, `findings` 두 키 |
| meta 필수 | `topic`, `entry_url`, `started_at`, `finished_at`, `elapsed_sec` |
| meta 선택 | `tool_version` |
| topic | 원문 표기와 예시에 맞춰 문자열 `TOPIC` 사용 |
| 시각·시간 | ISO 8601 시각, 총 소요시간은 초 단위 숫자 |
| findings | 모든 페이지 결과를 하나의 배열에 저장. 0건도 `[]` 필수 |
| 검출 필수 필드 | `id`, `url`, `is_violation`, `location`, `evidence_text`, `technique` |
| id | 파일 내 중복 불가 |
| technique | 필수 4종 중 단일 문자열. 배열·복수 코드 금지 |
| 원문 | `evidence_text`는 정규화 전 원본 그대로 보존 |
| 검출 단위 | `(url, location, technique)`마다 1건 |

동일 요소에 두 기법이 있으면 객체를 두 개 만듭니다. 같은 요소에 같은 기법의 문자열이 여러 개 있으면 1건입니다. 페이지별 배열을 만들지 않습니다.

### 위치와 URL

- `location`은 CSS 선택자가 원칙이며 한 요소를 정확히 가리켜야 합니다. 여러 요소가 매칭되면 오답 처리됩니다.
- 태그·클래스를 함께 적고 상위부터 ` > `로 연결합니다. 클래스가 없으면 `:nth-of-type()` 등을 사용합니다. 다른 표기여도 같은 요소를 정확히 가리키면 인정됩니다.
- 속성값은 큰따옴표로 표시합니다.
- iframe 내부는 `iframe[src="절대주소"] >>> 내부 선택자`로 표시합니다. 중첩되면 ` >>> `를 반복합니다.
- iframe 결과의 `url`은 발견한 상위 페이지 전체 URL로 기록하고, 프레임 경로는 `location`에 담는 방식을 개발 기본값으로 삼습니다. 원문의 iframe 예시(13쪽)에 따른 선택입니다.
- 채점에서는 URL 끝 `/`, HTTP·HTTPS 차이, `#` 이하를 무시합니다. 쿼리 값은 페이지를 구분하되 쿼리 항목 순서 차이는 무시합니다.
- 위 URL 비교 규칙은 **채점 기준**입니다. 크롤러에서 HTTP·HTTPS를 무조건 합치거나 의미 있는 쿼리를 제거하는 것은 별도 판단이 필요합니다.

### 추가 유형

필수 4종은 `result.json`에만 담고, 추가 유형은 `result_extra.json`에 분리합니다. 추가 결과는 `technique: "ETC"`, `extra_finding: "추가 유형 이름"`을 사용합니다. 원문 11쪽 필드 설명과 13쪽 예시의 필수 필드 표기에 차이가 있으므로, 개발 시에는 추가 결과에도 `is_violation`을 포함하는 보수적인 형식으로 작성합니다. 현재 저장소의 JSON Schema는 필수 4종 결과만 다룹니다.

## 평가와 일정

| 적격평가 | 배점 | 기준 |
| --- | --- | --- |
| 정답 검출 개수 | 45 | 정답 하위 URL과 검출 항목을 찾아낸 개수 |
| 정답 추출 정확도 | 35 | 유형·근거 위치 등 지정 필드 일치율, 전체 검출 대비 정탐 비율 |
| 검출 시간 | 20 | URL 입력/탐지 시작부터 완료까지. 30분 초과 시 이 항목 0점 |

정답 인정의 핵심은 `url`, `location`, `technique` 일치입니다. 원문은 정답 판정에 쓰지 않지만 필수이며 본심사 참고자료입니다. 필수 필드가 빠진 개별 항목은 채점 제외, 전체 파일 파싱 실패는 해당 회차 성능 점수 0점입니다. 파일 미생성·스키마 미준수는 평가 제외 사유가 될 수 있습니다. (6·10~14쪽)
